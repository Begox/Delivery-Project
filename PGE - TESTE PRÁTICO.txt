Teste Prático para Desenvolvedor Full Stack Pleno
Cenário
Você está atuando em um projeto existente de um aplicativo de entrega de comida, similar ao iFood.
Sua responsabilidade será implementar uma solução full stack completa, contemplando backend e frontend, garantindo a criação, autenticação, gerenciamento e consulta de pedidos de entrega.
A solução deverá seguir boas práticas modernas de arquitetura, segurança, integração REST, experiência do usuário, validação de dados e cobertura de testes automatizados.
________________


Objetivo
Desenvolver uma aplicação Full Stack utilizando:
* Backend em Java com Spring Boot
* Frontend em Angular
* Biblioteca visual PrimeNG
* Banco de dados PostgreSQL
* API REST
* Testes unitários com JUnit e Mockito
* Testes de interface com Jasmine/Karma
A aplicação deverá permitir:
* Cadastro e autenticação de usuários
* Criação de pedidos de entrega
* Consulta de pedidos
* Atualização de dados do usuário
* Controle de sessão/autenticação
* Navegação dinâmica baseada no estado do login
________________

Requisitos Funcionais
Backend
1. Cadastro de Usuário
O sistema deverá permitir o cadastro de novos usuários contendo:
* Nome Completo *
* CPF *
* Email *
* Senha *
* Telefone *
* Telefone Secundário
* CEP *
* Endereço *
* Local de Referência *
* = Preenchimento obrigatório
Regras obrigatórias de cadastro
CPF
* Deve ser único no sistema
* Não pode existir mais de um usuário com o mesmo CPF
Email
* Deve ser único no sistema
* Não pode existir mais de um usuário com o mesmo e-mail
Password Policy (Obrigatória)
 A senha deverá:
* possuir no mínimo 6 caracteres
* conter ao menos:
   * 1 letra maiúscula
   * 1 letra minúscula
   * 1 caractere especial
Exemplo válido:
* Senha@123
Identificador único
Ao cadastrar um usuário:
* será gerado um ID único
* o CPF e o e-mail ficarão permanentemente vinculados ao mesmo ID
________________


2. Autenticação de Usuário
O sistema deverá permitir login utilizando:
* CPF ou E-mail
* Senha
Após autenticação válida:
* o backend deverá gerar um token JWT
* o frontend deverá armazenar o token de autenticação
* as rotas privadas deverão utilizar autenticação baseada em token
As rotas autenticadas deverão receber token JWT no header utilizando o padrão:
Authorization: Bearer <token>
________________


3. Criação de Pedido
Somente usuários autenticados poderão criar pedidos.
O sistema deverá permitir a criação de pedidos contendo:
* endereço de coleta
* endereço de entrega
* descrição dos itens
* valor estimado calculado automaticamente (campo somente leitura)
* data/hora da solicitação
Regras obrigatórias do pedido
* endereço de coleta obrigatório
* endereço de entrega obrigatório
* valor estimado deve ser maior que zero
* o pedido somente poderá ser confirmado após cálculo válido da entrega
Segurança do pedido
O identificador do usuário NÃO deverá ser enviado manualmente pelo frontend.
O backend deverá identificar automaticamente o usuário autenticado através do token JWT.
________________


4. Consulta de Pedidos
O sistema deverá permitir:
* consultar pedidos do usuário autenticado
* listar pedidos anteriores
Exibir:
* data e hora do pedido
* valor
* descrição
* status do pedido
Status do pedido
O sistema deverá possuir os seguintes status:
* PENDING
* IN_PROGRESS
* DELIVERED
* CANCELED
________________


5. Atualização de Dados do Usuário
Usuários autenticados poderão:
* atualizar dados cadastrais
* alterar telefone
* alterar endereço
* alterar local de referência
________________


6. Tratamento de Erros
O backend deverá tratar adequadamente:
* campos obrigatórios ausentes
* CPF duplicado
* e-mail duplicado
* senha inválida
* token inválido
* usuário não autenticado
* valor inválido
* recurso não encontrado
As respostas de erro da API deverão seguir padrão consistente.
Exemplo:
{
 "timestamp": "2026-05-09T12:00:00",
 "status": 400,
 "message": "CPF já cadastrado"
}
________________


7. Cálculo Automático do Valor Estimado da Entrega
O sistema deverá calcular automaticamente o valor estimado da entrega com base na distância entre o endereço de coleta e o endereço de entrega.
O usuário deverá informar o endereço completo de coleta e o endereço completo de entrega, incluindo:
* rua
* número
* bairro
* cidade
* estado
* CEP (quando disponível)
O frontend NÃO deverá calcular manualmente o valor da entrega.
Todo o cálculo deverá ser realizado exclusivamente pelo backend.
________________


Integração com APIs de Geolocalização
O backend deverá utilizar integração com APIs públicas baseadas em OpenStreetMap para:
* conversão de endereço em coordenadas geográficas (latitude/longitude)
* cálculo de rota
* cálculo de distância
* cálculo de tempo estimado
APIs utilizadas
Geocodificação de endereço
 Utilizar serviço baseado em:
* OpenStreetMap Nominatim API
Responsável por:
* converter endereço completo em coordenadas geográficas
Cálculo de distância e tempo
 Utilizar serviço baseado em:
* OSRM API
Responsável por:
* calcular distância entre os endereços
* calcular tempo estimado da rota
________________


Fluxo obrigatório do cálculo
Frontend
O usuário deverá informar:
* endereço completo de coleta
* endereço completo de entrega
Após preenchimento:
* o frontend deverá enviar os dados ao backend
* o backend deverá calcular automaticamente:
   * distância
   * tempo estimado
   * valor estimado da entrega
Endpoint obrigatório
POST /api/orders/calculate-estimate
Request esperado
{
 "pickupAddress": "Av. Paulista, 1000, São Paulo - SP",
 "deliveryAddress": "Rua Augusta, 500, São Paulo - SP"
}
Response esperado
{
 "distanceKm": 5.2,
 "estimatedTimeMinutes": 20,
 "estimatedValue": 18.00
}
________________


Regra de cálculo da entrega
O backend deverá utilizar fórmula semelhante a:
valorEntrega = taxaBase + (distanciaKm * valorPorKm)
Exemplo:
* taxaBase = R$ 5,00
* valorPorKm = R$ 2,50
________________


Regras obrigatórias
* o frontend não poderá definir manualmente o valor da entrega
* o backend será responsável por todo o cálculo
* o valor deverá ser salvo no pedido após confirmação
* o sistema deverá validar endereços inválidos
* o sistema deverá tratar falhas de integração externa
* o sistema deverá impedir entregas acima da distância máxima permitida
________________


Distância máxima permitida
O sistema deverá possuir validação de distância máxima de entrega.
Exemplo:
* Máximo permitido: 30 KM
Caso ultrapasse o limite:
* o backend deverá retornar mensagem apropriada
* o pedido não poderá ser criado
________________
